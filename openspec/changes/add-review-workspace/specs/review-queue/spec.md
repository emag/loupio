# Spec Delta

## Purpose

Lupio の review-queue に関する外部から観測できる振る舞いを定義し、合意した MVP の利用手順と完了条件を検証できる契約にする。

## ADDED Requirements

### Requirement: 依頼の収集と手動追加
アプリは初回に未終了の個人・選択チーム宛ての依頼を要対応として収集し、GitHub PR URL でも追加できなければならない（MUST）。

#### Scenario: 同じ PR の取り込み
- **WHEN** 同じ PR が複数の収集元と手動追加に現れる
- **THEN** 一つの PR として扱い、依頼元を表示する

### Requirement: 対応状況の管理
アプリは要対応・相手待ち・対応済み・終了を区別し、手動で相手待ち・対応済みや自動判定を修正できなければならない（MUST）。

#### Scenario: 手動修正
- **WHEN** お礼の返信により要対応になった PR を対応済みにする
- **THEN** 対応済みとして保持され、同じ取得済み返信だけでは再度要対応にならない

### Requirement: 再確認の検知
アプリは追加コミット、作者の新規コメント・返信、自分へのメンション、個人宛て再レビュー依頼で要対応に戻し、理由を表示しなければならない（MUST）。自分自身と Bot のコメントは除外する。

#### Scenario: 作者からの返信
- **WHEN** 相手待ちの PR に作者から新規返信が来る
- **THEN** 要対応になり、返信が理由として表示される

### Requirement: コメントの除外
アプリは自分自身・Bot・メンションのない他者同士のコメントだけでは要対応に戻してはならない（MUST NOT）。

#### Scenario: Bot の通知
- **WHEN** 対応済み PR に Bot だけがコメントした
- **THEN** 対応済みを維持する

### Requirement: 追跡の継続
アプリは取り込み済み PR の依頼が解除されてもマージ・クローズまで追跡し、他メンバーの承認だけで対象外にしてはならない（MUST NOT）。

#### Scenario: 依頼解除後の変更
- **WHEN** 依頼解除済み PR に追加コミットが来る
- **THEN** 対象外指定がなければ要対応に戻る

### Requirement: チーム依頼の対象外指定
アプリは自分は対応しない指定と手動復帰を提供し、対象外 PR は追加コミットや通常の返信では復帰させず、個人宛ての新規依頼で復帰させなければならない（MUST）。

#### Scenario: 対象外への個人依頼
- **WHEN** 対象外 PR に新しい個人宛て依頼が来る
- **THEN** 対象外を解除し要対応に戻す

### Requirement: ドラフトの表示
アプリはドラフトを通常の要対応一覧から外して別表示し、解除時は要対応とし、ドラフト中の手動要対応指定を提供しなければならない（MUST）。

#### Scenario: ドラフト解除
- **WHEN** 追跡中のドラフトがレビュー可能になる
- **THEN** 通常の要対応一覧に表示する

### Requirement: 終了した PR
アプリはマージ・クローズした PR を終了として扱わなければならない（MUST）。

#### Scenario: 終了とコメントの同時取得
- **WHEN** マージ済み PR と新規コメントを取得する
- **THEN** 終了を優先し通常の要対応一覧から外す

### Requirement: 一覧の優先順
アプリは優先指定した PR を先頭にし、残りは対応待ちが長い順に並べ、依頼種別と再確認理由を表示しなければならない（MUST）。

#### Scenario: 再取得時の順序
- **WHEN** 新しいイベントのない PR を再取得する
- **THEN** 対応待ちの開始時刻を変えず順序を維持する
